# 질문 재작성 실험 (2026-11-21)

## 설정

- **켜기:** `RAG_QUERY_REWRITE=1` (기본 꺼짐). LLM(gpt-4o-mini)이 질문을 정책 용어 검색어로 바꿔요.
- **병합:** 원래 질문 검색과 재작성 질문 검색의 정책 순위를 RRF(k=10)로 합쳐요.
- **건너뜀:** 질문에 카탈로그 정책명(5글자 이상)이 이미 들어 있으면 재작성하지 않아요.
- **시간 제한:** 2초 안에 응답이 없거나 실패하면 원래 질문만으로 검색해요. 재시도하지 않아요.
- **캐시:** 성공한 재작성은 `.rag/policies.sqlite`의 `query_rewrites`에 저장해요.
- **응답 시간 측정:** 켬 실행 직전마다 캐시를 비워, 처음 받는 질문 기준으로 쟀어요. 검색 단계는 재작성, 질문 임베딩, 검색을 포함하고, 전체는 여기에 답변 생성을 더한 시간이에요. 평가는 2개 질문을 동시에 처리했어요.
- **조정:** dev 검색 평가로만 했어요. dev에서는 켬과 끔의 차이가 없어서 k는 기본값 10으로 뒀어요. test는 마지막에 한 번만 실행했어요.

## 해석

- **점수:** 세 세트 모두 오르지 않았고, test는 1문항 떨어졌어요.
- **떨어진 test 문항 (T019, T023):** 재작성이 "아동복지시설", "18세 이후" 같은 구별 단서를 버리고 "자립준비청년 자립수당"으로 일반화했어요. 그 바람에 다른 자립수당 게시물이 정답보다 위로 올라왔어요.
- **dev D016:** 재작성을 건너뛴 질문인데도 답변이 실패로 바뀌었어요. 답변 LLM의 실행 간 편차예요.
- **응답 시간:** 검색 단계 평균이 0.5~0.7초 늘었어요. 최대는 2.2초까지 갔고, 2초 시간 초과는 없었어요.
- **효과가 없었던 이유:** 정리된 세트는 질문에 구별 단서가 들어 있어서 지금 검색으로도 이미 대부분 찾아요(검색 상위5가 test 29/30). 재작성이 도울 여지가 거의 없었어요.

## 결론

test가 오르지 않았으므로 기본값(꺼짐)을 유지하는 게 맞아요. 코드는 꺼진 상태로 남겨 두었고, 꺼져 있으면 기존 검색 경로와 같아요.
